# Implementation status

## Contextual assistant and Google voice — current iteration

Ask PlantSense adds an authenticated contextual drawer with six in-tab exchanges, source inspection, saved deterministic INR cards and approved navigation. One bounded Gemini call answers a question; investigation agents and workflow authority are unchanged. Asset/incident consistency is checked server-side, and equipment-only context excludes unrelated latest incidents. All requests run through the shared serialized controller; long assistant requests cannot silently queue approvals. Context changes discard old answers and stop voice.

Google Speech-to-Text V2 global `short`, `en-IN`, receives bounded mono 16 kHz WAV. Users edit transcripts and explicitly send them. Google `en-IN-Wavenet-A` synthesis accepts only validated, staff-scoped answer references; playback is requested and cached in the tab. The exact transcription route has a 1 MiB JSON boundary; other routes retain 64 KiB. Transactional usage metadata adds audio seconds and synthesis characters without storing audio, chat or credentials. Questions have a ten-per-user UTC-day limit and share daily AI request/spend limits while retaining separate investigation allowances. Failed requests retain conservative charges and stable keys prevent rebilling.

## Evaluated local Gemini investigation — current iteration

Live Vertex Gemini is available through an explicit local override; base Compose remains scripted. The server freezes bounded read-only telemetry/baseline, dependency/production, reviewed-procedure and plant-scoped verified-repair evidence. An ADK investigator and evidence reviewer precede separate Reliability and Production assessments of the same deterministic calculation. Citations, schema, feasible preferences, currency narratives and safety assurance are validated. Sparse signals, sensor disagreement and historical origin enforce low confidence. Human authorization, exact calculation versions, technician work and qualifying post-repair observations remain authoritative.

Additive migration 6 introduces request usage accounting. SQLite reserves calls and estimated spending transactionally, retains unknown charges and preserves incident allowances across retries, restarts and UTC day boundaries. Live execution has a shared 120-second deadline, eight-call allowance and one retry per transient reviewer/specialist failure. Model usage appears separately from intervention costs. Credentials and the passing report are mounted read-only at runtime; neither enters the image or source control. See [local Gemini investigation](operations/live-gemini.md).

## Operational product foundation — completed iteration

The main application now requires staff access and uses versioned observation sources and historical import preview/commit. Replay controls, anonymous demo entry, generated supporting readings and selectable post-repair recovery have been removed from product pages. Missing current data remains unknown; measured output, rated capacity and configured impact estimates are separate.

Operational observations use reviewed envelopes, immutable original records, bounded batches and server-owned quality/detection. Historical and legacy records cannot authorize work or verify operational repairs. Maintenance eligibility is UTC-based, and technician completion waits for incoming post-repair observations.
